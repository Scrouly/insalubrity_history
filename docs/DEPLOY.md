# Раздача «Истории по вредности» на компьютеры кадровиков

## Как это устроено

```
Сервер: \\сервер\папка\InsalubrityHistory\
    current\      <- актуальная сборка (её обновляете вы)
    current.old\  <- предыдущая сборка (для отката)
    install\      <- install.bat + InsalubrityHistory.cmd (для новых компьютеров)

Компьютер кадровика:
    %LOCALAPPDATA%\InsalubrityHistory\app\   <- локальная копия программы (обновляется сама)
    %LOCALAPPDATA%\InsalubrityHistory\InsalubrityHistory.cmd + server.txt  <- запускатель
    %APPDATA%\InsalubrityHistory\            <- ДАННЫЕ пользователя: .env, month_overrides.json,
                                                hire_dates_override.json, backups\, crash.log
```

Обновление заменяет только `app\`. Папка данных никогда не трогается, поэтому у каждого
кадровика свои настройки и свои ручные правки. Положение окна и колонок хранится в реестре
(QSettings) и тоже остаётся.

## Вам: выпуск обновления

1. Внесите правки в код, поднимите номер в `version.py` (например, `1.0.0` -> `1.0.1`).
2. `scripts\build.bat` — прогоняет тесты (при ошибке сборка не начнётся), собирает `dist\InsalubrityHistory`.
3. `scripts\publish.bat \\сервер\папка\InsalubrityHistory` — копирует сборку на сервер.
   Путь можно один раз записать в файл `publish_target.txt` в корне проекта.
   Если номер версии на сервере уже такой же, publish откажется (иначе клиенты не поймут, что есть новая).

Откат: на сервере удалите папку `current`, переименуйте `current.old` в `current`.
Клиенты сравнивают версию «не равно», поэтому вернутся на старую при следующем запуске.

## Новый компьютер кадровика (один раз)

Запустить с сервера `\\сервер\папка\InsalubrityHistory\install\install.bat`.
Права администратора не нужны. Скрипт создаст ярлык «Insalubrity History» на рабочем столе
и запустит программу (первый запуск копирует её с сервера).

Затем в программе укажите папки DBF и RSV (кнопка настроек) — они сохранятся у этого пользователя.

## Что происходит при запуске

1. Запускатель смотрит `\\сервер\...\current\version.txt` и сравнивает с локальным.
2. Версии разные -> копирует во временную папку `app.new`, и только после полного копирования
   меняет её на `app`. Обрыв сети посреди копирования не ломает рабочую копию.
3. Сервер недоступен -> запускается локальная копия (но при недоступном сервере запуск
   может задержаться на время сетевого таймаута).
4. Если программа уже запущена, обновление пропускается (файлы заняты) и применится при
   следующем запуске.

## Если сервер переехал

В `%LOCALAPPDATA%\InsalubrityHistory\server.txt` лежит одна строка с путём к папке на сервере.
Можно поправить вручную или просто запустить новый `install.bat` ещё раз.

## .gitignore
